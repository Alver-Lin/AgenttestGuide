# 工程化与生态：交付一个可维护的 Python 项目

本篇对应蛇形图 **L7，节点 37–42**，前置为 [6-并发与异步](./6-并发与异步.md)。目标是让项目可以被别人安装、运行、检查和继续修改，而不只是“在我的电脑上能跑”。

示例面向 **Python 3.12**。普通 Python 代码块可独立运行；节点 42 标注文件名的代码块需要按目录保存后一起运行。项目以测评数据生成 Markdown 报告为主线，使用标准库实现业务，第三方工具负责测试、检查和构建。

## 37｜项目与依赖管理

### 37.1 区分项目、分发包与导入包

项目是代码、测试、文档和配置的整体；分发包是安装工具管理的发行单位；导入包是 `import` 时使用的名字。

本篇示例的项目分发名为 `scorekit-demo`，Python 导入名为 `scorekit`，命令名为 `score-report`。三者可以不同，但需要在文档中说清楚。

采用 `src` 布局时，业务包放在 `src/scorekit/`，测试放在 `tests/`。这种布局有助于发现“只在仓库根目录能导入、安装后不能导入”的问题。开发时通过可编辑安装让解释器找到包。

### 37.2 pyproject.toml 各部分负责什么

- `[build-system]`：声明构建后端及构建时需要的依赖。
- `[project]`：项目名、版本、支持的 Python 版本、运行依赖等元数据。
- `[project.scripts]`：安装后生成的命令行入口。
- `[project.optional-dependencies]`：可选依赖组，例如测试与开发工具。
- `[tool.ruff]`、`[tool.pytest.ini_options]` 等：各工具自己的配置。

`pyproject.toml` 不等于虚拟环境，也不自动锁定所有间接依赖。声明“支持哪些版本”与记录“这次实际选择哪些版本”是两个问题。

### 37.3 两条常用工作流

使用标准环境工具和 pip：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m pytest
```

Windows PowerShell 的激活命令通常为 `.venv\Scripts\Activate.ps1`。`-e` 是可编辑安装，适合开发；`.[dev]` 表示安装当前项目及其 `dev` 可选依赖。上面的命令需要先创建节点 42 的项目文件，并在项目根目录执行。

使用已安装的 uv 管理项目时，可以采用另一套流程：

```bash
uv lock
uv sync --extra dev --locked
uv run --extra dev --locked pytest
```

`uv lock` 更新锁文件；`--locked` 要求锁文件与项目声明一致，不允许自动改锁。`--extra dev` 对应本篇配置的可选依赖，不要与 `[dependency-groups]` 中名为 `dev` 的依赖组混淆。同步与锁定规则见 [uv 项目同步文档](https://docs.astral.sh/uv/concepts/projects/sync/)。

选择一种主要流程并记录下来即可。应用项目通常提交锁文件，用于协作和持续集成；发布的库则还需要在元数据中声明合理的兼容范围。锁文件也不能保证操作系统、原生库、外部接口和数据完全相同。

### 37.4 仓库应该保留什么

保留源码、测试、项目配置、必要的锁文件、使用说明与小型示例数据。通常忽略 `.venv/`、缓存、构建产物和本地私有配置。运行必须依赖的资源，应明确作为包数据、配置或外部服务提供，不能依赖作者电脑上的绝对路径。

**练习**：在新的临时目录建立项目，用新的虚拟环境安装，再从仓库以外的目录调用它。

**掌握标志**：能解释环境、依赖声明、锁文件、导入路径各自解决的问题。

## 38｜代码质量

### 38.1 格式、静态检查和测试各司其职

格式化让代码外观一致；静态规则检查发现常见错误和风格问题；类型检查发现类型约定不一致；测试验证实际行为。一个工具通过不能替代另外几项。

在节点 42 的完整项目中运行：

```bash
python -m ruff format --check .
python -m ruff check .
python -m mypy src
python -m pytest
```

修改格式时使用 `python -m ruff format .`。自动修复规则时先阅读差异，避免把修改当作无需审查的动作。Ruff 的检查与格式化是两个入口，见 [Ruff 文档](https://docs.astral.sh/ruff/)。

类型注解不会自动检查输入 JSON；运行时验证仍应写在边界函数里。测试通过也只说明覆盖到的场景满足预期。

### 38.2 pytest：让测试围绕输入和行为组织

节点 42 包含一组可以保存后执行的测试。需要掌握：

- 使用普通 `assert` 描述预期结果。
- 使用 `pytest.raises()` 验证拒绝非法输入。
- 使用 `@pytest.mark.parametrize()` 把同一种规则的多个边界列出来。
- 使用 `tmp_path` 创建彼此隔离的临时文件。
- 使用 `monkeypatch` 隔离环境变量、函数或其他外部条件。

fixture 用于准备测试所需的状态与资源。共享 fixture 也有生命周期和污染风险，不能为了减少几行代码就共享所有可变对象。可参见 [pytest fixture 文档](https://docs.pytest.org/en/stable/how-to/fixtures.html)。

### 38.3 将检查变成日常流程

本地先运行与改动相关的测试；提交前运行项目约定的完整检查。持续集成应从干净环境安装依赖，再执行相同命令。遇到失败先读错误位置、输入和预期，不要为了让检查变绿而删掉断言。

不要用覆盖率百分比代替测试设计。一个报告工具最有价值的测试包括：空数据、全部缺失、零分、边界分数、非法类型、读取失败、输出路径冲突，以及失败时是否错误地显示成功。

**练习**：故意把过滤条件改成 `if score`，确认零分测试能发现问题；修复后再运行整组测试。

**掌握标志**：能指出每项检查验证什么，也能说明它没有验证什么。

## 39｜日志与配置

### 39.1 日志用于解释程序的运行过程

库代码通常只创建 `logging.getLogger(__name__)`，由应用入口决定日志等级、格式和去向。不要让每个导入模块都调用 `basicConfig()` 或随意添加处理器。

```python
import io
import logging

stream = io.StringIO()
logger = logging.getLogger("scorekit.lesson39")
previous_level = logger.level
previous_propagate = logger.propagate
handler = logging.StreamHandler(stream)
handler.setFormatter(logging.Formatter("%(levelname)s %(message)s"))
logger.addHandler(handler)
logger.setLevel(logging.INFO)
logger.propagate = False
try:
    logger.info("已处理 %s 条记录", 5)
    print(stream.getvalue(), end="")
finally:
    logger.removeHandler(handler)
    handler.close()
    logger.setLevel(previous_level)
    logger.propagate = previous_propagate
```

```text
INFO 已处理 5 条记录
```

用 `logger.info("数量=%s", count)` 把格式化交给日志系统。`DEBUG` 用于诊断细节，`INFO` 记录关键过程，`WARNING` 提醒可恢复的异常情况，`ERROR` 表示操作失败。在 `except` 中用 `logger.exception()` 可以附带调用栈。

用户需要的报告写入文件或标准输出，诊断日志通常写标准错误。日志应保留任务编号、耗时或失败阶段，但不要记录凭据和不必要的个人信息。

### 39.2 配置应有明确优先级

常见约定是：命令行参数优先于环境变量，环境变量优先于配置文件，最后采用默认值。并不是所有项目都必须采用这一顺序，但要保持一致并提供说明。

```python
from collections.abc import Mapping


def read_threshold(cli_value: int | None, environment: Mapping[str, str]) -> int:
    value = cli_value if cli_value is not None else int(environment.get("SCORE_THRESHOLD", "60"))
    if not 0 <= value <= 100:
        raise ValueError("及格线必须在 0–100 之间")
    return value


print(read_threshold(None, {}))
print(read_threshold(None, {"SCORE_THRESHOLD": "75"}))
print(read_threshold(90, {"SCORE_THRESHOLD": "75"}))
```

```text
60
75
90
```

不要用 `cli_value or default` 处理数值配置，因为有效值 `0` 会被误判。布尔配置也不能简单写 `bool("false")`，它的结果是 `True`；需要明确接受哪些字符串。

配置校验最好在程序启动时完成，再将已验证的值传给业务函数。业务函数直接读取全局环境，会增加测试与复用难度。

**练习**：让及格线支持命令行和环境变量，验证 `0`、`100`、非法字符串和越界值。

**掌握标志**：能从日志理解失败阶段，能解释一个配置值最终从哪里获得。

## 40｜命令行与发布

### 40.1 argparse：把参数解析与业务分开

```python
import argparse

parser = argparse.ArgumentParser(description="生成测评报告")
parser.add_argument("input", help="输入 JSON 文件")
parser.add_argument("--output", default="report.md", help="输出 Markdown 文件")
parser.add_argument("--threshold", type=int, default=60, help="及格线")
args = parser.parse_args(["scores.json", "--threshold", "75"])
print(args.input)
print(args.output)
print(args.threshold)
```

```text
scores.json
report.md
75
```

示例传入参数列表方便测试；真实命令不传列表时，`parse_args()` 从命令行读取。`type=int` 负责转换，但不保证数值在业务范围内。

常见退出约定是：`0` 成功，非零失败；`argparse` 的参数错误通常以 `2` 退出。本篇应用用 `1` 表示读取、校验或写入失败。调用方应检查退出码，不能只看是否生成过一个同名文件。

### 40.2 包入口与命令入口

`python -m scorekit` 运行包内的 `__main__.py`；安装时 `[project.scripts]` 可以生成 `score-report` 命令。两种入口都调用同一个 `main()`，避免维护两套业务逻辑。

`main()` 接收可选参数列表并返回退出码，最外层用 `raise SystemExit(main())`。这样测试可以直接调用函数，不必每次启动子进程。

### 40.3 构建和发布是不同动作

完成节点 42 的项目并安装开发依赖后，在项目根目录执行：

```bash
python -m build
```

构建后通常在 `dist/` 得到源码分发包和 wheel。wheel 是安装格式，是否依赖平台取决于包中是否包含平台相关内容；不是所有 wheel 都能跨系统使用。

发布前应在一个新的虚拟环境中安装生成的 wheel，运行 `score-report --help` 并执行一次完整示例，检查有没有遗漏模块、资源和运行依赖。构建工具默认可能创建隔离环境并安装构建依赖，需要相应的依赖获取条件。

上传到包索引是单独的发布操作，还涉及名称、版本和账号。本教程只给出本地构建与验证流程，不需要把练习包上传。有关构建元数据和发行流程，可查 [Python Packaging 项目打包教程](https://packaging.python.org/en/latest/tutorials/packaging-projects/)。

**练习**：确认模块入口与命令入口生成相同报告，并验证帮助信息、输入错误和退出码。

**掌握标志**：能区分源码运行、可编辑安装、wheel 安装与对外发布。

## 41｜扩展与性能边界

### 41.1 优化顺序从测量开始

先测量并确认瓶颈，再考虑减少重复计算、改进数据结构、批量 IO、缓存和并发。只有确实需要时，再把部分计算交给原生库或编译扩展。

例如大量数值计算可能受益于专门的数组计算库；把缓慢的磁盘访问换成 C 语法，则未必解决问题。跨语言调用本身也有转换与复制成本，细碎调用可能抵消收益。

### 41.2 ctypes、Cython、cffi 分别是什么

`ctypes` 是标准库，可以访问 C 兼容的数据类型和动态库函数；`cffi` 是第三方的 C 接口工具；Cython 可以将带有类型信息的相关代码编译为扩展模块。它们都需要理解原生接口，不能把任意 Python 代码无条件变快。

先观察 Python 字符串如何变成带终止字节的 C 缓冲区：

```python
import ctypes

buffer = ctypes.create_string_buffer(b"abc")
print(buffer.value)
print(len(buffer))
print(buffer.raw)
```

```text
b'abc'
4
b'abc\x00'
```

真实调用动态库时，需要正确声明 `argtypes`、`restype`，明确字符串编码、指针有效期、结构体布局以及由谁释放内存。错误声明可能让整个进程崩溃，而不只是抛出 Python 异常。

### 41.3 扩展也会带来交付成本

原生扩展可能需要编译器、系统库和对应平台的 wheel；解释器版本、体系结构和 ABI 会影响兼容性。线程是否能并行执行原生代码，还取决于库及其 GIL 行为，不能只看“底层用了 C”。

在引入扩展之前，准备一个可复现的基准、明确的收益目标和跨环境验证方案。保持 Python 层接口稳定，让底层实现可以替换。

**练习**：为一个慢函数记录输入规模、耗时分布和调用次数；先提出一个纯 Python 改进，再判断是否需要扩展。

**掌握标志**：能用测量说明优化需求，并解释原生接口的内存与交付责任。

## 42｜选择一条业务主线

### 42.1 用一个可运行成果串起七层知识

可以从以下方向选择：Web 接口、数据处理、Agent 工具或测试自动化。先选一个明确输入和输出的小任务，把运行、失败提示、测试和说明做完整，再扩大范围。

对于“视频内容整理成带截图的 Markdown”这个方向，可以逐步拆成：取得已授权的视频或字幕、转录与时间戳、按时间抽帧、组织文档、保存来源和图片相对路径。每一步都应有独立输入输出，便于替换视频来源、转录服务和整理模型。先用本地样例数据跑通流程，再接外部平台。

**文件：`src/scorekit/__init__.py`**

```python
"""测评报告工具。"""
```

**文件：`src/scorekit/core.py`**

```python
import math
from dataclasses import dataclass


@dataclass(frozen=True)
class Record:
    name: str
    score: float | None


def parse_records(raw: object) -> list[Record]:
    if not isinstance(raw, list):
        raise ValueError("顶层数据必须是列表")
    records = []
    for index, item in enumerate(raw, start=1):
        if not isinstance(item, dict) or "name" not in item or "score" not in item:
            raise ValueError(f"第 {index} 条记录缺少 name 或 score")
        name, score = item["name"], item["score"]
        if not isinstance(name, str) or not name.strip():
            raise ValueError(f"第 {index} 条记录姓名无效")
        if score is not None:
            if isinstance(score, bool) or not isinstance(score, (int, float)):
                raise ValueError(f"第 {index} 条记录分数必须是数字或 null")
            if not 0 <= score <= 100 or not math.isfinite(score):
                raise ValueError(f"第 {index} 条记录分数必须在 0–100 之间")
            score = float(score)
        records.append(Record(name.strip(), score))
    return records


def render_report(records: list[Record], threshold: int = 60) -> str:
    if isinstance(threshold, bool) or not isinstance(threshold, int) or not 0 <= threshold <= 100:
        raise ValueError("及格线必须是 0–100 之间的整数")
    scores = [record.score for record in records if record.score is not None]
    average = f"{sum(scores) / len(scores):.2f}" if scores else "暂无数据"
    passed = sum(score >= threshold for score in scores)
    return (
        "# 测评报告\n\n"
        f"- 总人数：{len(records)}\n"
        f"- 有效成绩：{len(scores)}\n"
        f"- 缺失成绩：{len(records) - len(scores)}\n"
        f"- 及格线：{threshold}\n"
        f"- 及格人数：{passed}\n"
        f"- 平均分：{average}\n"
    )
```

`parse_records()` 位于外部数据进入业务的边界，负责验证；`render_report()` 接收已验证记录并输出字符串，不读文件、不依赖环境变量。`Record` 的类型注解不会自动执行校验，其他调用者也应遵守入口约定。

**文件：`src/scorekit/cli.py`**

```python
import argparse
import json
import logging
import os
from pathlib import Path

from .core import parse_records, render_report

logger = logging.getLogger(__name__)


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(description="将测评 JSON 转为 Markdown 报告")
    parser.add_argument("input", type=Path, help="输入 JSON 文件")
    parser.add_argument("--output", type=Path, default=Path("report.md"))
    parser.add_argument("--threshold", type=int, help="及格线，优先于 SCORE_THRESHOLD")
    args = parser.parse_args(argv)
    logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
    try:
        threshold = (
            args.threshold
            if args.threshold is not None
            else int(os.environ.get("SCORE_THRESHOLD", "60"))
        )
        if args.input.resolve() == args.output.resolve() or (
            args.output.exists() and args.input.samefile(args.output)
        ):
            raise ValueError("输入与输出不能是同一个文件")
        raw = json.loads(args.input.read_text(encoding="utf-8"))
        records = parse_records(raw)
        report = render_report(records, threshold)
        args.output.parent.mkdir(parents=True, exist_ok=True)
        args.output.write_text(report, encoding="utf-8")
    except (OSError, ValueError) as exc:
        logger.error("生成失败：%s", exc)
        return 1
    logger.info("已生成报告：%s", args.output)
    return 0
```

这里的 `ValueError` 分支也包含 JSON 解码和 UTF-8 解码等相关错误。输入与输出相同路径、符号链接指向同一文件、已有硬链接等情况都会被检查。示例不是处理恶意并发修改文件路径的安全组件。

同名输出会覆盖。读取和业务校验失败时不会开始写入；写入中断时并未保证原子替换，生产工具可进一步采用同目录临时文件加替换策略。失败后已有旧报告可能仍然存在，应以退出状态判断本次操作是否成功。
