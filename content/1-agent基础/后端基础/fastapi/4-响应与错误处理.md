## 1｜response_model：约定「返回长什么样」

**这一节解决的问题**：怎样保证响应字段稳定，并过滤不该对外的数据？

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class ScoreCreate(BaseModel):
    name: str
    score: int = Field(ge=0, le=100)


class ScoreOut(BaseModel):
    id: int
    name: str
    score: int
    passed: bool


@app.post("/scores", response_model=ScoreOut)
def create_score(payload: ScoreCreate):
    return {
        "id": 1,
        "name": payload.name,
        "score": payload.score,
        "passed": payload.score >= 60,
        "internal_note": "不要给客户端",  # 有 response_model 时默认会被丢掉
    }
```

作用：

1. **文档**：`/docs` 展示响应 schema；
2. **过滤**：默认只输出模型里声明的字段；
3. **校验**：返回数据不符合模型时，开发环境会暴露错误（便于及早发现）。

列表响应：

```python
@app.get("/scores", response_model=list[ScoreOut])
def list_scores():
    return [
        {"id": 1, "name": "小林", "score": 85, "passed": True},
        {"id": 2, "name": "小王", "score": 55, "passed": False},
    ]
```

## 2｜状态码

### 2.1 在装饰器上声明

```python
from fastapi import status


@app.post("/scores", response_model=ScoreOut, status_code=status.HTTP_201_CREATED)
def create_score(payload: ScoreCreate):
    return ScoreOut(
        id=1,
        name=payload.name,
        score=payload.score,
        passed=payload.score >= 60,
    )
```

常见约定：

| 场景 | 常用状态码 |
|------|------------|
| 查询成功 | 200 OK |
| 创建成功 | 201 Created |
| 删除成功且无正文 | 204 No Content |
| 客户端参数/校验问题 | 422（FastAPI 校验）或 400 |
| 未登录 | 401 |
| 无权限 | 403 |
| 资源不存在 | 404 |
| 服务内部错误 | 500 |

### 2.2 删除返回 204

```python
from fastapi import Response


@app.delete("/scores/{score_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_score(score_id: int):
    # 实际项目里在此删除；找不到则抛 404
    return Response(status_code=status.HTTP_204_NO_CONTENT)
```

204 表示成功但没有响应体，客户端不应期待 JSON。

## 3｜HTTPException：业务错误

**这一节解决的问题**：资源不存在、名称冲突等，怎样返回清晰的 4xx？

```python
from fastapi import HTTPException


SCORES = {
    1: {"id": 1, "name": "小林", "score": 85, "passed": True},
}


@app.get("/scores/{score_id}", response_model=ScoreOut)
def get_score(score_id: int):
    row = SCORES.get(score_id)
    if row is None:
        raise HTTPException(status_code=404, detail=f"成绩记录 {score_id} 不存在")
    return row
```

客户端会收到：

```http
HTTP/1.1 404 Not Found
Content-Type: application/json

{"detail":"成绩记录 9 不存在"}
```

`detail` 可以是字符串，也可以是字典/列表，便于结构化错误信息：

```python
raise HTTPException(
    status_code=409,
    detail={"code": "NAME_EXISTS", "message": "同名成绩已存在"},
)
```

**不要用 200 包一层 `{"success": false}` 假装失败。** HTTP 状态码本身就该表达成败；业务码可以额外放在 JSON 里，但不能替代状态码。

## 4｜统一异常处理（可选但实用）

当希望所有未捕获异常都返回统一 JSON 形状时，可注册处理器：

```python
from fastapi import Request
from fastapi.responses import JSONResponse


class AppError(Exception):
    def __init__(self, message: str, code: str = "APP_ERROR"):
        self.message = message
        self.code = code


@app.exception_handler(AppError)
async def app_error_handler(request: Request, exc: AppError):
    return JSONResponse(
        status_code=400,
        content={"code": exc.code, "message": exc.message},
    )


@app.get("/demo-error")
def demo_error():
    raise AppError("演示业务错误", code="DEMO")
```

`HTTPException` 已由框架处理；自定义异常适合表达领域错误。入门阶段先熟练 `HTTPException` 即可。

## 5｜响应头与自定义 Response

少数场景需要额外响应头（例如分页总数、下载文件名）：

```python
from fastapi import Response


@app.get("/scores")
def list_scores(response: Response):
    response.headers["X-Total-Count"] = "2"
    return [
        {"id": 1, "name": "小林", "score": 85, "passed": True},
        {"id": 2, "name": "小王", "score": 55, "passed": False},
    ]
```

普通 JSON 接口优先用 `return` + `response_model`；只有需要精细控制状态码/头/媒体类型时，再手写 `JSONResponse` / `Response`。

## 6｜调试时的阅读顺序

接口「不对」时，建议按这个顺序看：

1. **HTTP 状态码**：2xx / 4xx / 5xx；
2. **响应 JSON**：`detail` 或业务字段；
3. **若是 422**：读 `loc` 定位 path / query / body；
4. **若是 404/409**：检查自己的 `HTTPException` 逻辑；
5. **若是 500**：看运行 uvicorn 的终端堆栈。

与 Apifox 联调时，同时打开状态码和 Body 面板，避免只看「请求成功发送」而忽略 4xx。
