# FastAPI 请求体与校验：用 Pydantic 接住 JSON

本篇对应 [FastAPI 全景地图](./0-全景地图.md) 的第 **3** 层。

**学习目标**：会用 Pydantic `BaseModel` 定义请求体；能给字段加约束与示例；能处理嵌套模型与列表；理解校验失败时的 422 信息。

建议先完成 [2-路由与参数](./2-路由与参数.md)。

---

## 1｜为什么需要模型

**这一节解决的问题**：POST/PUT 的 JSON 怎样变成 Python 对象，并保证字段合法？

若只靠 `dict`，你要自己判断缺字段、类型不对、分数超出范围。Pydantic 模型让你**用类型注解描述数据形状**，FastAPI 在进业务逻辑前自动解析并校验。

```text
客户端 JSON  -->  Pydantic 校验  -->  你的函数拿到模型实例
                 失败则直接 422
```

## 2｜第一个请求体

### 2.1 定义模型并作为参数

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class ScoreCreate(BaseModel):
    name: str = Field(min_length=1, max_length=32, examples=["小林"])
    score: int = Field(ge=0, le=100, examples=[85])
    course: str = "Python"


@app.post("/scores")
def create_score(payload: ScoreCreate):
    # payload 已是通过校验的对象
    return {
        "id": 1,
        "name": payload.name,
        "score": payload.score,
        "course": payload.course,
        "passed": payload.score >= 60,
    }
```

请求示例：

```http
POST /scores
Content-Type: application/json

{
  "name": "小林",
  "score": 85
}
```

`course` 有默认值，可省略。函数参数是单一的 Pydantic 模型时，FastAPI 默认从 **JSON Body** 读取。

### 2.2 模型里常用写法

```python
from pydantic import BaseModel, Field, EmailStr


class StudentCreate(BaseModel):
    name: str
    email: EmailStr | None = None          # 需要 email-validator 包
    score: int = Field(ge=0, le=100)
    tags: list[str] = []                   # 默认空列表；注意可变默认在 Pydantic 中由框架处理
```

`EmailStr` 需额外安装：`python -m pip install email-validator`。入门阶段用 `str` 即可。

### 2.3 配置示例（方便文档展示）

```python
class ScoreCreate(BaseModel):
    name: str
    score: int = Field(ge=0, le=100)

    model_config = {
        "json_schema_extra": {
            "examples": [
                {"name": "小林", "score": 85},
                {"name": "小王", "score": 55},
            ]
        }
    }
```

`/docs` 里 Try it out 会带上这些示例，降低联调成本。

## 3｜嵌套与列表

### 3.1 嵌套模型

```python
class Student(BaseModel):
    name: str
    class_name: str = "一班"


class ScoreIn(BaseModel):
    student: Student
    score: int = Field(ge=0, le=100)


@app.post("/scores/nested")
def create_nested(payload: ScoreIn):
    return {
        "name": payload.student.name,
        "class_name": payload.student.class_name,
        "score": payload.score,
    }
```

请求体：

```json
{
  "student": {"name": "小林", "class_name": "二班"},
  "score": 90
}
```

### 3.2 列表 Body

```python
@app.post("/scores/batch")
def create_batch(items: list[ScoreCreate]):
    return {"count": len(items), "names": [i.name for i in items]}
```

请求体是 JSON 数组：

```json
[
  {"name": "小林", "score": 85},
  {"name": "小王", "score": 70}
]
```

## 4｜Body + 路径 / 查询一起用

```python
from typing import Annotated
from fastapi import Query


@app.put("/scores/{score_id}")
def replace_score(
    score_id: int,
    payload: ScoreCreate,
    notify: Annotated[bool, Query(description="是否通知助教")] = False,
):
    return {
        "id": score_id,
        "updated": payload.model_dump(),
        "notify": notify,
    }
```

来源分工：

- `score_id` → 路径；
- `payload` → JSON Body；
- `notify` → 查询参数。

把模型转成普通字典可用 `payload.model_dump()`（Pydantic v2）；只要字段可用 `payload.name`。

## 5｜校验失败怎么读

提交非法分数：

```json
{"name": "小林", "score": 120}
```

响应 **422**，`detail` 中 `loc` 会指向 `body` → `score`。比路径/查询参数的 422 多了一层 `body`，阅读方式相同：先看 `loc`，再看 `msg`。

业务规则（例如「同名不能重复」）不属于「类型/范围校验」，应在函数里判断并返回 4xx（下一篇用 `HTTPException`）。**Pydantic 管格式与字段约束，业务冲突管在你的逻辑里。**

## 6｜创建模型与响应模型可以分开

对外返回时，常常不想把内部字段全暴露。可以为「写入」和「读出」准备不同模型：

```python
class ScoreCreate(BaseModel):
    name: str
    score: int = Field(ge=0, le=100)


class ScoreOut(BaseModel):
    id: int
    name: str
    score: int
    passed: bool


@app.post("/scores", response_model=ScoreOut)
def create_score(payload: ScoreCreate) -> ScoreOut:
    return ScoreOut(
        id=1,
        name=payload.name,
        score=payload.score,
        passed=payload.score >= 60,
    )
```

`response_model` 的细节在下一篇展开；这里先建立「输入模型 ≠ 输出模型」的习惯。
