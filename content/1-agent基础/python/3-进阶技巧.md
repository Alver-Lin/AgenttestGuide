## 1. 推导式、迭代器与生成器

### 1.1 推导式

**定义**：用一行紧凑语法，从可迭代对象生成 `list` / `dict` / `set`；可加 `if` 过滤。嵌套过深时改回普通 `for`。

**类比**：流水线模具——原料进去，按规则一次成型出列表 / 字典 / 集合；模具太复杂就拆回手工组装。

**代码表现**：

```python
nums = [1, 2, 3, 4, 5]
print([n * n for n in nums if n % 2 == 1])
print({n: n * n for n in nums})
print({n % 3 for n in nums})
```

```text
[1, 9, 25]
{1: 1, 2: 4, 3: 9, 4: 16, 5: 25}
{0, 1, 2}
```

**使用场景**：批量映射分数、过滤及格项、从用例列表抽 id 去重。

**场景代码**：

```python
rows = [
    {"id": "1", "score": 0.9},
    {"id": "2", "score": 0.5},
    {"id": "3", "score": 0.85},
]
passed_ids = [row["id"] for row in rows if row["score"] >= 0.8]
score_map = {row["id"]: row["score"] for row in rows}
print(passed_ids)
print(score_map)
```

```text
['1', '3']
{'1': 0.9, '2': 0.5, '3': 0.85}
```

### 1.2 迭代器协议

**定义**：`for x in xs` 的本质是取迭代器，反复 `next`，直到抛出 `StopIteration`。`iter(obj)` 得到迭代器。

**类比**：点名册——每次叫下一个，叫完就停；`next` 是「下一位」。

**代码表现**：

```python
it = iter([10, 20])
print(next(it), next(it))
```

```text
10 20
```

再 `next(it)` 会抛 `StopIteration`（`for` 会自动吞掉它）。

**使用场景**：理解 `for` / 生成器为何「只能往前走」；自己实现可迭代对象时需要这个协议。

**场景代码**：

```python
scores = iter([0.9, 0.7])
first = next(scores)
second = next(scores)
print(first, second)
```

```text
0.9 0.7
```

### 1.3 生成器：惰性产出

**定义**：函数体里出现 `yield`，调用时不立刻跑完，而是返回**生成器**——每次要下一个值才继续执行。生成器表达式 `(expr for ...)` 同理。

**类比**：不是一次端出整桌菜，而是上完一道再做下一道——省内存，适合大文件边读边处理。

**代码表现**：

```python
from pathlib import Path

path = Path("scores.txt")
path.write_text("0.9\n\n0.7\n0.85\n", encoding="utf-8")


def read_scores(file_path: str):
    with open(file_path, encoding="utf-8") as file:
        for line in file:
            line = line.strip()
            if line:
                yield float(line)


print(list(read_scores("scores.txt")))
print(sum(n * n for n in range(5)))
```

```text
[0.9, 0.7, 0.85]
30
```

**使用场景**：逐行读 JSONL / 分数文件；流水线里不想一次载入全部数据。

**场景代码**：

```python
from pathlib import Path
import json

path = Path("cases.jsonl")
path.write_text(
    '{"id":"1","score":0.9}\n{"id":"2","score":0.4}\n',
    encoding="utf-8",
)


def iter_passed(file_path: str, threshold: float = 0.8):
    with open(file_path, encoding="utf-8") as file:
        for line in file:
            row = json.loads(line)
            if row["score"] >= threshold:
                yield row["id"]


print(list(iter_passed("cases.jsonl")))
```

```text
['1']
```

### 1.4 小结

小数据、要反复用 → 列表推导；大数据或流水线 → 生成器。

## 2. 闭包与装饰器

### 2.1 闭包：带配置的函数工厂

**定义**：内层函数引用了外层函数的变量，外层返回内层后，那些变量仍被「记住」——这就是闭包。

**类比**：定制印章——工厂按阈值做好一枚章；之后每次盖章都带着当初设好的阈值。

**代码表现**：

```python
def make_threshold_filter(threshold: float):
    def passed(score: float) -> bool:
        return score >= threshold

    return passed


is_good = make_threshold_filter(0.8)
print(is_good(0.91))
print(is_good(0.5))
```

```text
True
False
```

**使用场景**：为不同任务生成不同及格线判断器；固定某种清洗规则后反复调用。

**场景代码**：

```python
def make_normalizer(lower: bool = True):
    def normalize(text: str) -> str:
        text = text.strip()
        return text.lower() if lower else text

    return normalize


norm = make_normalizer(True)
print(norm("  OK \n"))
```

```text
ok
```

### 2.2 装饰器：统一加料

**定义**：装饰器是「接收函数，返回函数」的语法糖（`@decorator`）；常用于在不改原逻辑的前提下加日志、计时、鉴权等横切能力。`@functools.wraps` 用来保留原函数名与文档。

**类比**：给快递盒统一贴面单——商品不变，外面多一层可追踪信息。

**代码表现**：

```python
import functools
import time


def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} 耗时 {elapsed:.4f}s")
        return result

    return wrapper


@timed
def rank_cases(scores: list[float]) -> list[float]:
    return sorted(scores, reverse=True)


print(rank_cases([0.2, 0.9, 0.5]))
```

```text
rank_cases 耗时 0.0000s
[0.9, 0.5, 0.2]
```

（耗时因机器而异，数量级通常很小。）

**使用场景**：给打分 / 模型调用统一加计时或日志，而不改函数本体。

**场景代码**：

```python
import functools


def logged(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        print(f"{func.__name__} -> {result}")
        return result

    return wrapper


@logged
def exact_match(predict: str, expect: str) -> float:
    return 1.0 if predict.strip() == expect.strip() else 0.0


exact_match("通过", "通过")
```

```text
exact_match -> 1.0
```

### 2.3 带参数的装饰器

**定义**：先写一层「接收参数、返回真正装饰器」的外函数，才能写成 `@retry(times=2)` 这种带配置的形式。

**类比**：先选「重试几次」的套餐，再把面单打印机调成该套餐去贴每个包裹。

**代码表现**：

```python
import functools


def retry(times: int = 3):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_error = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except TimeoutError as exc:
                    last_error = exc
                    print(f"第 {attempt} 次失败: {exc}")
            raise RuntimeError(f"{func.__name__} 重试耗尽") from last_error

        return wrapper

    return decorator


@retry(times=2)
def fetch_output():
    raise TimeoutError("模型超时")


try:
    fetch_output()
except RuntimeError as exc:
    print("最终:", exc)
```

```text
第 1 次失败: 模型超时
第 2 次失败: 模型超时
最终: fetch_output 重试耗尽
```

真实项目请收窄异常类型，并加退避，避免疯狂打接口。

**使用场景**：模型 API 偶发超时、网络抖动时的有限次重试。

**场景代码**：

```python
import functools


def retry(times: int = 3):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_error = None
            for _ in range(times):
                try:
                    return func(*args, **kwargs)
                except TimeoutError as exc:
                    last_error = exc
            raise last_error

        return wrapper

    return decorator


attempts = {"n": 0}


@retry(times=3)
def flaky():
    attempts["n"] += 1
    if attempts["n"] < 3:
        raise TimeoutError("暂时失败")
    return "ok"


print(flaky())
print("实际尝试次数:", attempts["n"])
```

```text
ok
实际尝试次数: 3
```

### 2.4 小结

闭包记住配置；装饰器横向复用横切逻辑；记得 `wraps`。

## 3. 类型注解与 Pythonic 习惯

### 3.1 类型注解

**定义**：用注解声明参数与返回值的预期类型（如 `list[str]`、`Callable[...]`）。默认不在运行时强制检查，主要服务阅读、IDE 与静态检查工具。

**类比**：图纸上的尺寸标注——机器仍可按经验组装，但对齐图纸更不容易接错线。

**代码表现**：

```python
from __future__ import annotations

from typing import Callable

ScoreFn = Callable[[str, str], float]


def run(cases: list[tuple[str, str]], scorer: ScoreFn) -> float:
    if not cases:
        return 0.0
    return sum(scorer(p, e) for p, e in cases) / len(cases)


def exact(predict: str, expect: str) -> float:
    return 1.0 if predict.strip() == expect.strip() else 0.0


print(run([("通过", "通过"), ("失败", "通过")], exact))
```

```text
0.5
```

**使用场景**：评测入口函数、可替换打分器接口、团队协作时减少「传错类型」。

**场景代码**：

```python
from typing import Callable

NormalizeFn = Callable[[str], str]


def apply(text: str, fn: NormalizeFn) -> str:
    return fn(text)


print(apply("  Hi ", str.strip))
```

```text
Hi
```

### 3.2 Pythonic 习惯

**定义**：更符合 Python 社区惯例的写法——清晰、显式、善用标准库惯用语，而不是堆技巧。

**类比**：本地交通规则——能达目的的开法很多，按当地习惯开更少挨按喇叭。

**代码表现**：

```python
from pathlib import Path
from dataclasses import dataclass


@dataclass
class Row:
    case_id: str
    score: float


rows = [Row("1", 0.9), Row("2", 0.4)]
passed = [row.case_id for row in rows if row.score >= 0.8]
path = Path("out") / "ids.txt"
path.parent.mkdir(parents=True, exist_ok=True)
path.write_text("\n".join(passed) + "\n", encoding="utf-8")
print(path.read_text(encoding="utf-8").strip())
print(f"通过 {len(passed)} 条")
```

```text
1
通过 1 条
```

更 Pythonic 的习惯：

- 用 `with` 管资源
- 用推导式表达清晰的映射 / 过滤
- 用 `Path`、f-string、dataclass
- 显式优于隐式：少依赖隐藏全局状态

**使用场景**：整理评测脚本风格，让后人（包括一个月后的自己）读得快。

**场景代码**：

```python
scores = [0.2, 0.9, 0.55]
# 清晰过滤，而不是手动建空列表再层层 append（当然那种也对）
high = [s for s in scores if s >= 0.8]
print(high)
```

```text
[0.9]
```

### 3.3 小结

注解帮助阅读和 IDE，不替代测试；习惯服务于可读性，不服务于炫技。

## 4. 数据库入门：SQLite

### 4.1 为什么需要持久化

**定义**：进程结束时，内存里的变量会消失。要把评测结果留下来、并按条件查询，需要持久化存储；**SQLite** 是标准库自带的嵌入式数据库，无需单独装服务器。

**类比**：草稿纸（内存）散会就扔；账本（数据库）可以按日期、按客户翻找。

**代码表现**：

```python
import sqlite3
from pathlib import Path

db_path = Path("eval.db")
conn = sqlite3.connect(db_path)
try:
    conn.execute(
        """
        CREATE TABLE IF NOT EXISTS results (
            case_id TEXT PRIMARY KEY,
            score REAL NOT NULL,
            model TEXT NOT NULL
        )
        """
    )
    conn.execute(
        "INSERT OR REPLACE INTO results(case_id, score, model) VALUES (?, ?, ?)",
        ("case-01", 0.92, "gpt-test"),
    )
    conn.commit()
    rows = conn.execute(
        "SELECT case_id, score FROM results WHERE score >= ? ORDER BY score DESC",
        (0.8,),
    ).fetchall()
    print(rows)
finally:
    conn.close()
```

```text
[('case-01', 0.92)]
```

要点：

1. 用 `?` 占位符传参，不要用 f-string 拼 SQL。
2. 写操作后 `commit()`。
3. 生产多用户并发再考虑 MySQL / PostgreSQL。

**使用场景**：本地保存每次跑分；按模型 / 阈值筛选历史结果。

**场景代码**：

```python
import sqlite3
from pathlib import Path

conn = sqlite3.connect(Path("eval.db"))
try:
    conn.execute(
        "CREATE TABLE IF NOT EXISTS results (case_id TEXT PRIMARY KEY, score REAL, model TEXT)"
    )
    conn.executemany(
        "INSERT OR REPLACE INTO results(case_id, score, model) VALUES (?, ?, ?)",
        [
            ("c1", 0.9, "gpt-test"),
            ("c2", 0.6, "gpt-test"),
            ("c3", 0.95, "local"),
        ],
    )
    conn.commit()
    avg = conn.execute(
        "SELECT AVG(score) FROM results WHERE model = ?",
        ("gpt-test",),
    ).fetchone()[0]
    print(avg)
finally:
    conn.close()
```

```text
0.75
```

### 4.2 JSON 文件 vs SQLite

**定义**：JSON / JSONL 适合交换与归档；需要频繁「按条件查询、聚合」时，SQLite 更合适。

**类比**：JSON 像整本打印好的报告；SQLite 像带目录和检索的档案柜。

**代码表现**：

```python
import json
from pathlib import Path

report = {"average": 0.85, "model": "gpt-test"}
Path("report.json").write_text(
    json.dumps(report, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
loaded = json.loads(Path("report.json").read_text(encoding="utf-8"))
print(loaded["average"], loaded["model"])
```

```text
0.85 gpt-test
```

**使用场景**：对外交付用 JSON；自己反复筛历史分数用 SQLite。

**场景代码**：

```python
# 同一批结果：文件归档 + 库内可查（示意组合）
import json
from pathlib import Path

Path("archive.json").write_text(
    json.dumps([{"id": "c1", "score": 0.9}], ensure_ascii=False),
    encoding="utf-8",
)
print(Path("archive.json").read_text(encoding="utf-8"))
```

```text
[{"id": "c1", "score": 0.9}]
```

### 4.3 小结

内存易失；本地实验优先 SQLite；传参用 `?`，写完要 `commit`。

## 5. 综合示例：迷你评测器

### 5.1 把三篇串起来

**定义**：迷你评测器 = 用例结构（dataclass）+ 可替换打分函数 + 跑批评分 + JSON 报告 + `__main__` 入口。

**类比**：一条最小装配线——来料（用例）→ 质检仪（scorer）→ 出厂报告（JSON）。

**代码表现**：

```python
from __future__ import annotations

import json
from dataclasses import dataclass
from pathlib import Path
from typing import Callable


ScoreFn = Callable[[str, str], float]


@dataclass
class Case:
    case_id: str
    expect: str
    predict: str


def exact_match(predict: str, expect: str) -> float:
    return 1.0 if predict.strip() == expect.strip() else 0.0


def run_eval(cases: list[Case], scorer: ScoreFn) -> dict:
    details = []
    for case in cases:
        score = scorer(case.predict, case.expect)
        details.append({"id": case.case_id, "score": score})
    average = sum(item["score"] for item in details) / len(details)
    return {"average": average, "details": details}


def save_report(report: dict, path: str | Path) -> None:
    target = Path(path)
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_text(
        json.dumps(report, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )


dataset = [
    Case("1", "通过", "通过"),
    Case("2", "拒绝", "我无法回答"),
]
result = run_eval(dataset, exact_match)
save_report(result, "output/report.json")
print(result["average"])
print(result["details"])
```

```text
0.5
[{'id': '1', 'score': 1.0}, {'id': '2', 'score': 0.0}]
```

**使用场景**：Agent 评测脚手架的最小形态；后续可换 scorer、加装饰器、写入 SQLite。

**场景代码**（换成「包含即得分」）：

```python
from dataclasses import dataclass
from typing import Callable


@dataclass
class Case:
    case_id: str
    expect: str
    predict: str


def contains_match(predict: str, expect: str) -> float:
    return 1.0 if expect.strip() in predict else 0.0


def run_eval(cases: list[Case], scorer: Callable[[str, str], float]) -> float:
    return sum(scorer(c.predict, c.expect) for c in cases) / len(cases)


dataset = [
    Case("1", "完成", "任务已完成"),
    Case("2", "拒绝", "我无法回答"),
]
print(run_eval(dataset, contains_match))
```

```text
1.0
```

可继续演进：

- 换成类形式的 `ContainsScorer().score`
- 用 `@timed` / `@retry` 包住模型调用
- 把结果额外写入 SQLite

### 5.2 小结

先跑通最小闭环，再往上叠模块、异常、持久化与装饰器。

## 6. 练习与学习路线回顾

### 6.1 练习

1. 写 `@retry(times=3)`，**只**捕获 `TimeoutError`，并打印第几次重试。
2. 用生成器逐行读取 JSONL 用例，边读边打分，不要一次性 `read().splitlines()` 也可以实现。
3. 用 SQLite 建表保存 `case_id, score, model, created_at`，并查询某模型的平均分。
4. 把综合示例拆成包：`cases.py` / `metrics.py` / `runner.py`，保证能跑通入口。

### 6.2 三篇路线回顾

| 篇目 | 你应该能做到 |
| --- | --- |
| 基础语法 | 写短脚本：类型、分支循环、容器、函数 |
| 核心机制 | 拆模块、处理异常、读写 JSON、用类建模 |
| 进阶技巧 | 推导式/生成器、装饰器、持久化、迷你评测器 |

建议小项目闭环：读 JSONL 用例 → 调打分函数 → 写 JSON 报告 →（可选）写入 SQLite。这正是 Agent 评测脚手架的最小形态。
