## 7｜模块与包

**这一节解决的问题**：代码多了以后怎样拆开，又怎样让拆开的代码协同工作？

### 7.1 模块、包和导入

在本篇的常见场景中，一个 `.py` 文件就是一个模块。模块将相关的函数、类和常量放在一起，并提供独立的命名空间。

包用于组织模块。本篇采用带 `__init__.py` 的普通包；Python 还支持命名空间包，入门阶段先不展开。

```python
import math
from pathlib import Path
import json as js

print(math.sqrt(16))
print(Path("report.md").suffix)
print(js.dumps({"passed": True}))
```

```text
4.0
.md
{"passed": true}
```

- `import math`：导入模块，通过 `math.sqrt` 访问其中的名字。
- `from pathlib import Path`：把模块中的指定名字绑定到当前作用域。
- `import json as js`：导入后使用别名。

`from x import y` 仍然需要加载模块 `x`，并不是只执行文件里某个函数的定义。尽量少用 `from x import *`，否则难以判断名字来自哪里。

### 7.2 第一次把函数拆到另一个文件

新建 `module_demo/` 文件夹，并将下面两段代码分别保存。

**文件：`module_demo/metrics.py`**

```python
def average(scores):
    if not scores:
        return None
    return sum(scores) / len(scores)
```

**文件：`module_demo/main.py`**

```python
from metrics import average

print(f"平均分：{average([85, 58, 92]):.2f}")
```

在终端进入 `module_demo/`，再执行：

```bash
python main.py
```

```text
平均分：78.33
```

这里 `metrics.py` 负责计算，`main.py` 负责调用和展示。以后另一个程序需要计算平均分时，可以复用 `average()`，不用再复制函数。

### 7.3 __name__ 与入口保护

直接运行一个文件时，它的 `__name__` 是 `"__main__"`；作为模块导入时，通常是相应的模块名。

```python
def greet():
    return "模块已准备好"

if __name__ == "__main__":
    print(greet())
```

```text
模块已准备好
```

把这段代码保存为一个 `.py` 文件直接运行，会打印结果；被其他文件导入时，受入口条件保护的打印不会执行。

**导入并不只是读取函数目录。** 导入过程中会执行模块顶层代码，因此不要在顶层直接下载大文件、等待用户输入或批量改写业务数据。将实际任务放进函数，由入口主动调用。

模块通常在首次导入后缓存，再次导入不会自动重新执行全部代码；不要依靠“重复 import”来重复执行任务。

### 7.4 包结构与相对导入

当模块开始增多，可以按同一个业务组织成包。创建以下三个文件：

**文件：`package_demo/evalkit/__init__.py`**

```python
# 本文件标识普通包；初期可以保持为空。
```

**文件：`package_demo/evalkit/metrics.py`**

```python
def is_passed(score, threshold=60):
    return score >= threshold
```

**文件：`package_demo/evalkit/__main__.py`**

```python
from .metrics import is_passed


def main():
    print(is_passed(85))


if __name__ == "__main__":
    main()
```

在 `package_demo/` 目录运行：

```bash
python -m evalkit
```

```text
True
```

`-m` 表示按模块或包运行；运行包时会执行它的 `__main__.py`。`.metrics` 前面的点表示从当前包查找模块。

这里不要改成直接运行 `python evalkit/__main__.py`，因为直接按文件执行时，包上下文可能不存在，相对导入就会失败。

包外代码也可以写绝对导入，例如 `from evalkit.metrics import is_passed`，前提是该包位于解释器能找到的位置。后续安装项目时，会进一步处理这个问题。

### 7.5 导入失败从哪里排查

遇到 `ModuleNotFoundError` 或 `ImportError`，先按顺序检查：

1. 名字是否拼写正确，文件是否真的存在。
2. 从哪里启动程序，是按文件执行还是按包运行。
3. 当前解释器是不是安装了所需依赖的那个环境。
4. 自己的文件是否命名为 `json.py`、`typing.py` 等，遮住了同名标准库。
5. 两个模块是否互相导入，并在对方还没初始化完成时访问了它的名字。

循环导入不应靠随意调整导入顺序碰碰运气。可以把双方共用的定义移到第三个模块，使依赖方向更清楚。

### 7.6 怎样划分模块职责

按职责拆，而不是按行数平均切。一个小型成绩程序可以有：

- `models.py`：描述成绩记录及其校验规则。
- `storage.py`：读取输入文件、写入报告。
- `reporting.py`：统计成绩并生成报告内容。
- `__main__.py`：连接流程，处理面向用户的提示和退出状态。

不需要每个函数单独一个文件。先把重复、相互关联且边界明确的逻辑放在一起。

**本节练习**：把 L1 的平均分函数单独放进模块，从另一个文件导入；再尝试按包运行。

**过关标准**：能解释模块和包的区别，知道为什么需要入口保护，能够正确使用 `python -m` 与包内相对导入。

## 8｜环境与依赖

**这一节解决的问题**：怎样让不同项目使用各自的依赖，并让其他人知道运行程序需要什么？

### 8.1 标准库、自定义模块与第三方包

`json`、`pathlib`、`copy`、`dataclasses` 等属于标准库，安装 Python 后通常就能导入，不需要再用 pip 安装。

你编写的 `metrics.py` 是自定义模块；`httpx`、`pytest` 等属于第三方项目，需要在相应环境中安装后才能使用。

安装名称和导入名称不保证一致。看到某个 `import` 报错时，应查看该项目文档确认需要安装什么，而不是直接猜同名包。

### 8.2 创建虚拟环境

虚拟环境为项目隔离 Python 包。两个项目可以各自安装依赖，减少版本相互影响。

在自己的练习项目目录执行：

```bash
python -m venv .venv
```

macOS / Linux 的常见激活方式：

```bash
source .venv/bin/activate
```

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
```

激活后确认解释器和 pip：

```bash
python -c "import sys; print(sys.executable)"
python -m pip --version
```

路径应该指向当前练习项目的 `.venv`。退出激活状态可运行 `deactivate`。

激活主要是调整当前终端的命令查找路径；**不激活也可以使用环境里的解释器**。macOS / Linux 示例：

```bash
.venv/bin/python -m pip --version
```

Windows 示例：

```powershell
.\.venv\Scripts\python.exe -m pip --version
```

如果 PowerShell 不允许执行激活脚本，可以直接使用解释器路径，无须为了练习而放宽整个系统的脚本策略。

`.venv` 不应存放业务源码，也通常不提交到 Git；换机器时重建环境，而不是直接复制整个虚拟环境。虚拟环境隔离包，但不自动隔离网络、文件权限或操作系统。参见 [Python venv 文档](https://docs.python.org/3/library/venv.html)。

### 8.3 用对应解释器安装依赖

以下是第三方包安装示例，不是运行本篇综合项目的必要步骤：

```bash
python -m pip install httpx
python -m pip show httpx
python -m pip check
```

`python -m pip` 明确使用当前解释器对应的 pip，减少“安装成功但导入失败”的环境错位问题。

`pip check` 用于发现已安装包之间已声明的依赖冲突，不代表业务功能已经测试通过。

### 8.4 requirements.txt：告诉 pip 安装什么

`requirements.txt` 是 pip 可读取的安装清单。可以包含包名、版本约束以及其他安装选项。

例如下面的文件内容表示需要安装 `httpx`：

```text
httpx
```

安装清单中的依赖：

```bash
python -m pip install -r requirements.txt
```

如果想记录当前环境已经安装的版本，可以执行：

```bash
python -m pip freeze > requirements.txt
```

这会**覆盖同名文件**，应在确认目标文件后执行。`freeze` 是环境快照，可能包含间接依赖和实验时装过的包；它不等于自动判断出了项目真正需要的最小依赖，也不能单独保证跨系统完全复现。

日常要分清“我主动依赖哪些库”和“当前环境总共装了哪些库”。

### 8.5 pyproject.toml：描述项目及工具配置

`pyproject.toml` 用于保存项目元信息、依赖声明、构建配置和工具配置。下面是一份用于说明字段的配置示例，需要配合真实包源码使用：

```toml
[build-system]
requires = ["setuptools"]
build-backend = "setuptools.build_meta"

[project]
name = "score-study-demo"
version = "0.1.0"
requires-python = ">=3.10"
dependencies = []

[tool.setuptools.packages.find]
where = ["."]
include = ["score_app*"]
```

这里声明项目不依赖第三方运行库，并指定构建时使用 setuptools。`name` 是发行项目名称，不要求与 Python 导入包名 `score_app` 相同。

对于配置正确、具有实际包源码的项目，开发时可以使用可编辑安装：

```bash
python -m pip install -e .
```

它让当前环境可以使用这份源码，适合边改边开发。构建工具和依赖在缺失时仍可能需要下载；可编辑安装也不意味着任何配置修改都会自动生效。

`pyproject.toml` 不等于锁文件。依赖范围、已解析的具体版本、环境恢复流程是相关但不同的事情，锁定工具和发布流程放到 L7 再深入。参见 [Python Packaging：编写 pyproject.toml](https://packaging.python.org/en/latest/guides/writing-pyproject-toml/)。

**本节练习**：在练习目录创建 `.venv`，分别查看系统解释器与虚拟环境解释器路径，解释为什么 `python -m pip` 更容易对应到当前环境。

**过关标准**：能分清标准库与第三方包，知道依赖装进哪个环境，能区分 requirements 安装清单与项目配置。

## 9｜异常处理

**这一节解决的问题**：当输入不合法、文件不存在或操作失败时，怎样明确反馈并保留原因？

### 9.1 异常表示什么

异常表示程序无法按当前路径继续完成某个操作。可以捕获已预期的异常、改用其他策略，也可以让异常向调用方传播。

```python
try:
    score = float("不是分数")
except ValueError:
    print("分数必须是数字")
```

```text
分数必须是数字
```

只捕获自己知道如何处理的错误。输入转换可能产生 `ValueError`，但如果变量根本未定义，那是另外一个问题。

### 9.2 try / except / else / finally

- `try`：执行可能失败的操作。
- `except`：匹配并处理异常。
- `else`：`try` 正常完成后执行。
- `finally`：离开该结构时执行清理，不论走成功还是异常路径；进程被强制终止等情况不在正常语言流程内。

```python
try:
    score = float("85")
except ValueError:
    print("转换失败")
else:
    print(f"转换成功：{score:.1f}")
finally:
    print("本次处理结束")
```

```text
转换成功：85.0
本次处理结束
```

`try` 范围应尽量小，否则容易把后续代码中的意外错误也当成输入错误。`else` 或异常处理代码中出现的新异常，不会被同一结构前面的 `except` 再次捕获。

不要在 `finally` 中随意写 `return`，它可能覆盖原来的返回值或压掉正在传播的异常。

### 9.3 主动抛出异常

数据能转换成数字，不代表它符合业务要求。下面把“分数必须是 0–100 的有限数值”作为规则：

```python
def validate_score(score):
    if isinstance(score, bool) or not isinstance(score, (int, float)):
        raise TypeError("分数必须是数值")
    if not 0 <= score <= 100:
        raise ValueError("分数必须在 0 到 100 之间")
    return score

try:
    validate_score(120)
except (TypeError, ValueError) as exc:
    print(exc)
```

```text
分数必须在 0 到 100 之间
```

这里显式排除布尔值，因为 `bool` 是 `int` 的子类，但 `True` 不应被当成业务分数。范围判断也会拒绝无穷大和 NaN；本例不接受缺失值，是否接受 `None` 需要根据具体函数的约定决定。

不要用 `assert` 代替对外部输入的校验。断言适合检查程序内部预期，在某些运行选项下可能被移除。

### 9.4 自定义异常与异常链

自定义异常可以让调用方识别某一类业务失败。使用 `raise ... from ...` 可以在换成业务错误描述的同时保留底层原因。

```python
class InvalidScoreError(ValueError):
    pass


def parse_score(text):
    try:
        return float(text)
    except ValueError as exc:
        raise InvalidScoreError(f"无法识别分数：{text}") from exc


try:
    parse_score("通过")
except InvalidScoreError as exc:
    print(exc)
    print(type(exc.__cause__).__name__)
```

```text
无法识别分数：通过
ValueError
```

这一节先把 `class InvalidScoreError(ValueError)` 理解为“定义一种 ValueError 的子类”，类和继承将在第 12 节完整展开。

如果只想把原异常继续抛出，在 `except` 内使用裸 `raise`。不要把所有错误都转换成没有上下文的“失败”。

### 9.5 到哪一层处理错误

常见分工是：底层提供准确错误，调用层补充任务上下文，入口决定怎样告知用户。

例如，读取文件的函数发现文件不存在，可以让 `FileNotFoundError` 传播；入口提示“找不到输入文件”，并以非零退出码结束。统计函数不应悄悄把读取失败变成零分，否则会生成看似成功但内容错误的报告。

避免以下模式：

- `except: pass`：吞掉所有异常，还可能拦住用户中断。
- 捕获错误后直接返回空列表，却让调用方分不清“确实没有数据”和“根本没读成功”。
- 在每一层都打印同一条完整错误，导致重复日志。
- 自动无限重试所有错误，包括永远不会靠重试解决的格式错误。

### 9.6 traceback 与日志

`traceback` 能输出或取得异常调用栈，帮助定位错误发生在哪一条调用路径。`logging.exception()` 通常在 `except` 中使用，记录消息并附带当前异常信息。

```python
import traceback

try:
    int("错误输入")
except ValueError:
    details = traceback.format_exc()
    print("ValueError" in details)
```

```text
True
```

面向用户的提示可以简洁，开发排错时则需要保留足够上下文。不要把密钥或整份敏感输入写进日志。

**本节练习**：写一个分数解析函数，分别试数字文本、非数字文本和超出范围的分数，让入口给出不同提示。

**过关标准**：能选择具体异常类型，知道异常链有什么用，能解释为什么失败不能悄悄变成空结果。

## 10｜文件与序列化

**这一节解决的问题**：怎样把内存中的数据保存下来，并在下一次运行时正确读回？

### 10.1 pathlib：用对象处理路径

`Path` 表示路径。创建一个 `Path` 对象不会立即创建文件；拼接路径也不会自动创建目录。

```python
from pathlib import Path

path = Path("data") / "scores.json"
print(path.name)
print(path.stem)
print(path.suffix)
print(path.parent.name)
```

```text
scores.json
scores
.json
data
```

常用操作包括：`exists()` 检查是否存在，`is_file()` 判断是否为文件，`mkdir()` 创建目录，`glob()` 查找匹配路径。

相对路径通常相对于**当前工作目录**，不是自动相对于 `.py` 文件所在目录。若确实需要脚本旁的资源，可以在真实脚本中基于 `Path(__file__).resolve().parent` 定位；交互环境中不一定存在 `__file__`。

### 10.2 文本文件的读取与写入

下面使用 `TemporaryDirectory` 准备临时空间，退出后自动清理示例文件：

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    root = Path(folder)
    path = root / "output" / "note.txt"
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text("小林：85\n", encoding="utf-8")
    print(path.read_text(encoding="utf-8"), end="")
    print(path.exists())
```

```text
小林：85
True
```

`write_text()` 会覆盖已有文件，`read_text()` 一次读取全部文本。大文件可考虑逐行处理。

明确指定编码能减少跨环境差异。读取失败时不要随意用忽略错误的参数丢弃字节，应先确认原文件的编码与完整性。

### 10.3 open 模式与 with

常用模式：

- `"r"`：读取，文件必须存在。
- `"w"`：写入，已有内容会被截断。
- `"a"`：追加到末尾，文件不存在时创建。
- `"x"`：只创建新文件；同名文件存在时失败。
- 加 `"b"`：二进制模式，例如 `"rb"`、`"wb"`。

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "notes.txt"
    with path.open("w", encoding="utf-8") as file:
        file.write("第一条\n")
    with path.open("a", encoding="utf-8") as file:
        file.write("第二条\n")
    with path.open("r", encoding="utf-8") as file:
        for line in file:
            print(line.rstrip("\n"))
    print(file.closed)
```

```text
第一条
第二条
True
```

`with` 管理资源的进入和退出，文件即使在块内出现异常，正常的退出流程也会关闭它。**自动关闭不等于事务回滚**：写入一半时发生错误，之前写入的内容不一定恢复。

### 10.4 二进制文件

二进制模式处理 `bytes`，不指定文本编码。图片、压缩包等内容不能直接当 UTF-8 文本读取。

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "sample.bin"
    path.write_bytes(bytes([0, 1, 255]))
    print(list(path.read_bytes()))
```

```text
[0, 1, 255]
```

字符串要写成字节时先编码，字节要解释成文本时再按实际编码解码。这与 L1 中的 `str`、`bytes` 正好衔接。

### 10.5 JSON：交换结构化数据

序列化是把内存对象转成便于保存或传输的形式；反序列化是把它读回来。

JSON 常用于列表、字典、字符串、数字、布尔值和空值的交换：

```python
import json

record = {"name": "小林", "score": None, "passed": False}
text = json.dumps(record, ensure_ascii=False)
print(text)
loaded = json.loads(text)
print(loaded["score"] is None)
print(loaded["passed"] is False)
```

```text
{"name": "小林", "score": null, "passed": false}
True
True
```

`dumps()` 和 `loads()` 处理字符串；`dump()` 和 `load()` 处理文件对象。`ensure_ascii=False` 让中文直接显示，文件采用什么编码仍由文件打开方式决定。

JSON 使用双引号、`true`、`false`、`null`，与 Python 字面量语法不同。不要用 `eval()` 读取 JSON。

### 10.6 JSON 文件与业务校验

```python
import json
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "scores.json"
    rows = [{"name": "小林", "score": 85}]
    with path.open("w", encoding="utf-8") as file:
        json.dump(rows, file, ensure_ascii=False, indent=2, allow_nan=False)
    with path.open("r", encoding="utf-8") as file:
        loaded = json.load(file)
    print(loaded[0]["name"], loaded[0]["score"])
```

```text
小林 85
```

解析成功只说明文本满足解析器要求，不代表满足业务规则。仍要检查顶层是不是列表、每条记录是不是字典、字段是否齐全、分数范围是否正确。

注意类型边界：

- 元组编码后会变成 JSON 数组，读回通常是列表。
- 标准 JSON 对象的键是字符串，不适合无损保存任意 Python 字典键。
- 集合、日期对象、自定义类实例不能直接按默认规则编码。
- 严格 JSON 不接受 NaN 或 Infinity；`allow_nan=False` 可以让编码遇到这些浮点值时明确失败。

### 10.7 JSONL：一行一条记录

JSONL 约定每行是一份完整 JSON，适合逐条处理用例、日志或评测结果。

```python
import json
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "scores.jsonl"
    rows = [{"name": "小林", "score": 85}, {"name": "小周", "score": 58}]
    with path.open("w", encoding="utf-8") as file:
        for row in rows:
            file.write(json.dumps(row, ensure_ascii=False) + "\n")
    with path.open("r", encoding="utf-8") as file:
        for line_number, line in enumerate(file, start=1):
            row = json.loads(line)
            print(line_number, row["name"])
```

```text
1 小林
2 小周
```

写 JSONL 时不要对单条记录使用多行缩进。实际读取时，应明确空行和坏行的处理策略；需要拒绝时报告行号，而不是悄悄跳过后又声称处理了所有记录。

### 10.8 配置文件与错误位置

简单程序可以使用 JSON 保存及格线、输入路径等配置，但配置文件依然需要校验。

排查文件问题时，先区分：路径错误、权限不足、编码不匹配、JSON 语法错误，还是业务字段不合法。它们应得到不同的描述。

`path.exists()` 只能反映检查时的状态；检查之后文件仍可能变化。因此真正读写时依然要准备处理 `OSError` 等异常，不能认为“检查过存在”就必然读取成功。

## 11｜作用域与拷贝

**这一节解决的问题**：同名变量指向哪里，函数能否改外面的值，复制容器后是否还会相互影响？

### 11.1 LEGB：名字通常按什么顺序查找

函数内读取名字时，可以先用 LEGB 理解常见查找顺序：

- **L，Local**：当前函数的局部作用域。
- **E，Enclosing**：外层函数的作用域。
- **G，Global**：当前模块的全局作用域。
- **B，Builtins**：内置名称，例如 `len`、`print`。

```python
label = "模块级"


def outer():
    label = "外层函数"

    def inner():
        print(label)

    inner()


outer()
print(label)
```

```text
外层函数
模块级
```

这里没有修改模块级的 `label`，只是外层函数定义了同名局部变量。类体、推导式等还有额外规则，先掌握普通函数场景。

### 11.2 局部赋值与 UnboundLocalError

如果一个名字在函数内被赋值，且没有使用 `global` 或 `nonlocal` 声明，它通常会被视为该函数的局部名字。

```python
count = 1


def increase():
    count = count + 1
    return count


try:
    increase()
except UnboundLocalError:
    print("局部 count 在赋值前被读取")
```

```text
局部 count 在赋值前被读取
```

如果逻辑只是计算新值，显式传参和返回通常更清楚：

```python
def increase(count):
    return count + 1

count = 1
count = increase(count)
print(count)
```

```text
2
```

### 11.3 global：重新绑定模块级名字

```python
count = 0


def increase():
    global count
    count += 1


increase()
print(count)
```

```text
1
```

`global` 指当前模块的名字，不是所有模块共享的“宇宙全局变量”。它容易增加隐式依赖；配置和状态可以通过参数或对象传递时，优先考虑更明确的方式。

### 11.4 nonlocal 与闭包作用域

`nonlocal` 用于重新绑定外层函数中已经存在的名字。

```python
def make_counter():
    count = 0

    def next_count():
        nonlocal count
        count += 1
        return count

    return next_count


counter = make_counter()
print(counter())
print(counter())
other = make_counter()
print(other())
```

```text
1
2
1
```

返回的函数仍然能够访问对应外层函数的变量，这就是闭包的一种典型用法。两次 `make_counter()` 创建了不同的状态。这里只理解名字来自哪里，闭包的设计与组合放到 L3 深入。

### 11.5 修改对象不等于重新绑定名字

```python
def append_score(scores):
    scores.append(90)


def replace_scores(scores):
    scores = [100]
    return scores


original = [85]
append_score(original)
print(original)
replacement = replace_scores(original)
print(original)
print(replacement)
```

```text
[85, 90]
[85, 90]
[100]
```

函数形参接收的是同一个对象的引用。`append()` 修改共享对象；`scores = [100]` 重新绑定局部名字，不会让调用方的名字自动改指向新列表。

修改模块级列表的内容，也不必因为它定义在模块级就写 `global`；只有要重新绑定该名字时才涉及相应声明。

### 11.6 赋值、浅拷贝与深拷贝

```python
import copy

original = {"name": "小林", "scores": [85]}
alias = original
shallow = original.copy()
deep = copy.deepcopy(original)

original["scores"].append(90)
original["name"] = "小周"

print(alias is original)
print(shallow["name"], shallow["scores"])
print(deep["name"], deep["scores"])
```

```text
True
小林 [85, 90]
小林 [85]
```

- **赋值**：`alias` 和 `original` 是同一个字典的两个名字。
- **浅拷贝**：外层字典不同，但内部列表仍然共享。
- **深拷贝**：在这个嵌套容器例子中，内部列表也独立复制。

`list.copy()`、列表切片、`dict.copy()` 和 `copy.copy()` 常用于浅拷贝。`deepcopy()` 不等于所有东西都能任意复制；文件句柄、连接、共享资源等需要按对象语义处理。

只需要复制一层时，不要为了“保险”无条件深拷贝全部数据。

### 11.7 重复引用的常见陷阱

```python
rows = [[]] * 3
rows[0].append(85)
print(rows)

independent = []
for _ in range(3):
    independent.append([])
independent[0].append(85)
print(independent)
```

```text
[[85], [85], [85]]
[[85], [], []]
```

`[[]] * 3` 重复的是对同一个内部列表的引用。需要独立的容器时，每次都要创建新的对象。

L1 中的可变默认参数、这里的嵌套浅拷贝与列表重复，本质上都需要回答：**几个名字或位置是否引用同一个可变对象？**

**本节练习**：准备一份包含标签列表的记录，分别赋值、浅拷贝、深拷贝，再修改标签，先预测结果再运行。

**过关标准**：能解释 LEGB，分清 `global` 与 `nonlocal`，知道共享引用何时会导致联动修改。

## 12｜面向对象

**这一节解决的问题**：如何把一类数据及相关操作放在一起，并明确对象的规则和职责？

### 12.1 类、实例、属性与方法

类描述一类对象；实例是按这个类创建出的具体对象；属性保存状态；方法描述对象能执行的行为。

```python
class ScoreRecord:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def is_passed(self, threshold=60):
        return self.score >= threshold


record = ScoreRecord("小林", 85)
print(record.name)
print(record.is_passed())
```

```text
小林
True
```

`self` 指向当前实例。调用 `record.is_passed()` 时，Python 会把这个实例传给方法的第一个参数。

`__init__` 负责初始化实例，不应返回业务结果。不要把方法写成到处读取无关全局变量的函数，而应明确依赖实例属性和参数。

### 12.2 实例属性与类属性

```python
class Report:
    category = "成绩报告"

    def __init__(self):
        self.names = []


first = Report()
second = Report()
first.names.append("小林")
print(first.category)
print(first.names)
print(second.names)
```

```text
成绩报告
['小林']
[]
```

`category` 是类属性；`self.names` 是每次初始化时创建的实例属性。把 `names = []` 直接写到类体中，会让未覆盖该属性的实例共享同一个列表，通常不符合“每份报告自己的名单”的需求。

### 12.3 dataclass：减少数据类样板代码

当对象主要用于保存字段时，可以使用 `dataclass` 自动生成初始化、表示和相等比较等方法。

```python
from dataclasses import dataclass, field, asdict


@dataclass
class ScoreRecord:
    name: str
    score: float
    tags: list[str] = field(default_factory=list)


first = ScoreRecord("小林", 85)
second = ScoreRecord("小周", 58)
first.tags.append("第一轮")
print(asdict(first))
print(second.tags)
```

```text
{'name': '小林', 'score': 85, 'tags': ['第一轮']}
[]
```

这里的 `name: str`、`tags: list[str]` 是类型注解，先理解为说明字段预期类型；完整类型提示在 L3 学习。

**dataclass 不会仅凭注解自动校验或转换传入值。** 业务校验需要自己写，例如在 `__post_init__()` 中处理。`default_factory=list` 会为每个实例创建新的默认列表。

`asdict()` 可以把数据类转成字典结构，但其中的值仍需符合 JSON 编码规则，才能直接保存为 JSON。参见 [Python dataclasses 文档](https://docs.python.org/3/library/dataclasses.html)。

### 12.4 封装与 property

封装是把相关状态和操作放在一起，通过清楚的接口维护规则。`_name` 这样的单下划线名称表示内部实现约定，不是权限控制。

```python
class Scorer:
    def __init__(self, threshold=60):
        self.threshold = threshold

    @property
    def threshold(self):
        return self._threshold

    @threshold.setter
    def threshold(self, value):
        if isinstance(value, bool) or not isinstance(value, (int, float)):
            raise TypeError("及格线必须是数值")
        if not 0 <= value <= 100:
            raise ValueError("及格线必须在 0 到 100 之间")
        self._threshold = value


scorer = Scorer()
print(scorer.threshold)
scorer.threshold = 80
print(scorer.threshold)
try:
    scorer.threshold = 120
except ValueError as exc:
    print(exc)
```

```text
60
80
及格线必须在 0 到 100 之间
```

`property` 让调用方仍以属性形式访问，却能在读取或赋值时执行逻辑。设置器内部使用另一个属性 `_threshold` 存值，避免对 `self.threshold` 重复赋值造成递归调用。

### 12.5 继承、重写与 super

继承适合表达“某类对象也是另一类对象”，子类可以复用父类并重写部分行为。

```python
class Scorer:
    def __init__(self, threshold=60):
        self.threshold = threshold

    def is_passed(self, score):
        return score >= self.threshold


class StrictScorer(Scorer):
    def __init__(self):
        super().__init__(threshold=90)


print(Scorer().is_passed(85))
print(StrictScorer().is_passed(85))
```

```text
True
False
```

在这个单继承例子中，`super()` 用于复用父类初始化逻辑。这个例子只是展示语法；如果区别只有及格线参数，直接写 `Scorer(threshold=90)` 往往就足够，不必专门建子类。

### 12.6 多态、鸭子类型与组合

多态可以体现为：同一段调用代码面对不同对象，得到各自实现的行为。Python 常依赖鸭子类型，重点看对象是否提供所需行为，不一定要求继承同一个父类。

```python
class PlainFormatter:
    def format(self, name):
        return f"姓名：{name}"


class MarkdownFormatter:
    def format(self, name):
        return f"**姓名**：{name}"


def render(formatter, name):
    return formatter.format(name)


print(render(PlainFormatter(), "小林"))
print(render(MarkdownFormatter(), "小林"))
```

```text
姓名：小林
**姓名**：小林
```

这两个格式化器没有共同的自定义父类，但都能接受 `format(name)` 调用。

如果一个报告服务需要一个格式化器，可以把它作为参数或属性传进去，这属于组合。报告服务“使用格式化器”，并不意味着它“是一种格式化器”，因此不一定适合继承。

### 12.7 实例方法、类方法与静态方法

```python
class ScoreRecord:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def is_passed(self):
        return self.score >= 60

    @classmethod
    def from_dict(cls, data):
        return cls(data["name"], data["score"])

    @staticmethod
    def is_valid_score(value):
        return (
            not isinstance(value, bool)
            and isinstance(value, (int, float))
            and 0 <= value <= 100
        )


record = ScoreRecord.from_dict({"name": "小林", "score": 85})
print(record.is_passed())
print(ScoreRecord.is_valid_score(120))
```

```text
True
False
```

- 实例方法接收 `self`，适合使用当前对象状态。
- 类方法接收 `cls`，适合备用构造方式，如从字典创建对象。
- 静态方法不自动接收实例或类，适合放在类名下的相关工具逻辑；如果没有明确归属，也可以写成模块函数。

这个语法示例的 `from_dict()` 尚未调用校验方法，定义了校验函数不等于所有创建路径都自动经过校验。下一节的完整项目会落实输入检查。

### 12.8 什么时候使用类

当多个函数共同操作一组状态，或者某类记录有明确的字段与规则时，类会帮助组织代码。

只做一次简单转换的纯函数，不一定需要包装成类。可以让数据类负责记录，让普通函数负责读写，让服务类保存及格线等配置；不必所有逻辑都采用同一种组织形式。

**本节练习**：定义成绩记录类和带及格线的报告类；加入无效姓名、缺失字段与非法分数检查；确认不同实例的可变数据不共享。

**过关标准**：能用类组织数据和行为，知道 dataclass 的便利与边界，能解释继承、组合和三种方法的区别。

#### 数据类：让进入程序的记录符合约定

**文件：`score_project/score_app/__init__.py`**

```python
# 成绩报告程序包。
```

**文件：`score_project/score_app/models.py`**

```python
from dataclasses import dataclass


@dataclass
class ScoreRecord:
    name: str
    score: float | None

    def __post_init__(self):
        if not isinstance(self.name, str) or not self.name.strip():
            raise ValueError("姓名必须是非空字符串")
        self.name = self.name.strip()
        if self.score is None:
            return
        if isinstance(self.score, bool) or not isinstance(self.score, (int, float)):
            raise ValueError("分数必须是数值或 null")
        if not 0 <= self.score <= 100:
            raise ValueError("分数必须在 0 到 100 之间")

    @classmethod
    def from_dict(cls, data):
        if not isinstance(data, dict):
            raise ValueError("每条成绩必须是 JSON 对象")
        if "name" not in data or "score" not in data:
            raise ValueError("每条成绩都必须包含 name 和 score")
        return cls(name=data["name"], score=data["score"])
```

`float | None` 表达“数值字段可以缺失”的类型提示；实际接受整数或浮点数的规则由显式校验决定。额外字段在本例中不参与处理。这里没有把字符串 `"85"` 自动转成数值，避免悄悄接受不符合输入约定的数据。

#### 文件层：保留错误原因与记录位置

**文件：`score_project/score_app/storage.py`**

```python
import json
from pathlib import Path

from .models import ScoreRecord


class DataFormatError(ValueError):
    pass


def load_records(path):
    path = Path(path)
    try:
        with path.open("r", encoding="utf-8") as file:
            raw = json.load(file)
    except UnicodeDecodeError as exc:
        raise DataFormatError("输入文件必须使用 UTF-8 编码") from exc
    except json.JSONDecodeError as exc:
        raise DataFormatError(f"JSON 语法错误：第 {exc.lineno} 行第 {exc.colno} 列") from exc

    if not isinstance(raw, list):
        raise DataFormatError("JSON 顶层必须是成绩列表")

    records = []
    for index, item in enumerate(raw, start=1):
        try:
            record = ScoreRecord.from_dict(item)
        except ValueError as exc:
            raise DataFormatError(f"第 {index} 条记录不合法：{exc}") from exc
        records.append(record)
    return records


def save_report(path, text):
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(text, encoding="utf-8")
```

输入文件不存在、权限不足等 `OSError` 留给入口处理。输入格式错误则用 `DataFormatError` 表达，并保留底层原因。

```python
                continue
            valid.append(record)
            total_score += record.score
            if record.score >= self.threshold:
                passed_names.append(record.name)

        average = total_score / len(valid) if valid else None
        pass_rate = len(passed_names) / len(valid) if valid else None
        return {
            "total": len(records),
            "valid": len(valid),
            "missing": len(records) - len(valid),
            "passed": len(passed_names),
            "average": average,
            "pass_rate": pass_rate,
            "passed_names": passed_names,
        }

    def render(self, records):
        summary = self.summarize(records)
        average_text = "暂无数据"
        rate_text = "暂无数据"
        if summary["average"] is not None:
            average_text = f"{summary['average']:.2f}"
            rate_text = f"{summary['pass_rate']:.1%}"

        lines = [
            "# 测评成绩报告",
            "",
            f"- 测评人数：{summary['total']}",
            f"- 有效成绩：{summary['valid']}",
            f"- 缺失成绩：{summary['missing']}",
            f"- 及格人数：{summary['passed']}（及格线 {self.threshold:g} 分）",
            f"- 平均分：{average_text}",
            f"- 及格率：{rate_text}",
            "",
            "## 及格名单",
            "",
        ]
        if summary["passed_names"]:
            for name in summary["passed_names"]:
                # 将姓名显示为文字，避免姓名中的 Markdown 符号改变报告结构。
                plain_name = " ".join(name.splitlines())
                escaped_name = html.escape(plain_name, quote=False).replace("\\", "\\\\")
                for symbol in "`*_[]":
                    escaped_name = escaped_name.replace(symbol, "\\" + symbol)
                lines.append(f"- {escaped_name}")
        else:
            lines.append("无")
        return "\n".join(lines) + "\n"
```

`ScoreReport` 保存及格线配置；`summarize()` 返回数据，`render()` 返回 Markdown 文本，二者都不直接写文件。姓名中的换行和格式符号会在展示前处理，避免干扰报告结构；这不会改变数据类中的姓名。

#### 程序入口：连接流程并处理失败

**文件：`score_project/score_app/__main__.py`**

```python
import argparse
import sys

from .reporting import ScoreReport
from .storage import DataFormatError, load_records, save_report


def main():
    parser = argparse.ArgumentParser(description="从 JSON 成绩生成 Markdown 报告")
    parser.add_argument("input", help="输入 JSON 文件路径")
    parser.add_argument("output", help="输出 Markdown 文件路径；已有文件会被覆盖")
    parser.add_argument("--threshold", type=float, default=60, help="及格线，默认 60")
    args = parser.parse_args()

    try:
        reporter = ScoreReport(args.threshold)
        records = load_records(args.input)
        text = reporter.render(records)
        save_report(args.output, text)
    except (DataFormatError, OSError, ValueError) as exc:
        print(f"处理失败：{exc}", file=sys.stderr)
        return 1

    print(f"报告已生成：{args.output}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`argparse` 是标准库命令行参数工具，这里先学会读取路径与可选及格线。`sys.stderr` 用于输出错误信息；`SystemExit` 把返回值作为进程退出码：本例成功为 0，处理失败为 1，参数用法错误由 argparse 自己反馈。

入口捕获可预期的数据和文件错误，未预期的编程错误仍应暴露出来排查。示例没有自动重试和后台任务。

#### 检查边界情况

- 输入空列表：不除零，平均分和及格率显示“暂无数据”。
- 所有分数为 `null`：计为缺失，不伪造平均零分。
- 只有零分：有效成绩为 1，平均分为 `0.00`。
- 分数刚好 60：默认及格线下应及格。
- 及格线改为 90：示例只有小陈及格，平均分仍是 `58.75`。
- 分数为字符串、布尔值、负数或超过 100：明确拒绝并指出记录位置。
- 缺少字段、姓名为空、顶层不是列表：作为输入格式错误处理。
- 文件不存在、编码不正确、JSON 语法损坏：提示失败，不输出成功信息。

每次测试使用独立的练习输入文件，观察提示与退出状态。输入错误时，已有旧报告不会自动删除，不能把旧文件误认为本次生成成功。
