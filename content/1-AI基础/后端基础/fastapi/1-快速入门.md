# FastAPI 快速入门：从安装到第一个接口

本篇对应 [FastAPI 全景地图](./0-全景地图.md) 的第 **1** 层。

**学习目标**：理解 FastAPI 解决什么问题；能在虚拟环境中安装依赖；能写出并启动第一个接口；能打开自动文档做试调。

示例面向 Python **3.10+**、FastAPI **0.100+**。终端命令统一写 `python`，若系统使用 `python3` 请相应替换。

---

## 1｜FastAPI 是什么

**这一节解决的问题**：为什么选 FastAPI，它和「写个 Python 脚本」有什么不同？

### 1.1 一句话定位

**FastAPI** 是用 Python 编写的现代 Web 框架，专门用来做 **HTTP API**（给前端、移动端、其他服务调用的接口）。你写的是带类型注解的 Python 函数；框架负责路由匹配、参数解析、数据校验，并自动生成 OpenAPI 文档。

和普通脚本的区别：

| | 普通脚本 | FastAPI 服务 |
|--|----------|--------------|
| 触发方式 | 你在终端执行一次 | 一直监听端口，随时响应请求 |
| 输入 | 命令行参数 / 文件 | HTTP：方法 + URL + 头 + 体 |
| 输出 | 打印到终端 | HTTP 状态码 + JSON 等响应体 |
| 调用方 | 主要是你自己 | 浏览器、Apifox、前端、其他后端 |

### 1.2 核心特点（入门够用）

- **快**：基于 Starlette（Web 部分）和 Pydantic（数据校验）。
- **类型驱动**：函数参数写了类型，框架就知道怎么解析和校验。
- **自动文档**：启动后自带 Swagger UI（`/docs`）和 ReDoc（`/redoc`）。
- **与 REST 风格契合**：路径 + HTTP 方法组织接口，详见 [RESTful 使用方法](../RESTful使用方法.md)。

官方文档：[FastAPI](https://fastapi.tiangolo.com/zh/)。

## 2｜安装与启动

**这一节解决的问题**：环境怎么准备，服务怎么跑起来？

### 2.1 创建项目目录与虚拟环境

```bash
mkdir score-api && cd score-api
python -m venv .venv
```

macOS / Linux 激活：

```bash
source .venv/bin/activate
```

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
```

虚拟环境的含义与好处见 [Python 语言地基 · 虚拟环境与 conda](../python/1-语言地基.md)。

### 2.2 安装依赖

```bash
python -m pip install "fastapi[standard]"
```

`fastapi[standard]` 会装上运行服务常用的 **uvicorn** 等组件。也可以分开安装：

```bash
python -m pip install fastapi uvicorn
```

把版本记下来，方便复现：

```bash
python -m pip freeze > requirements.txt
```

### 2.3 最小可运行示例

新建 `main.py`：

```python
from fastapi import FastAPI

app = FastAPI(title="成绩 API", description="测评成绩入门示例", version="0.1.0")


@app.get("/")
def read_root():
    return {"message": "你好，FastAPI！"}


@app.get("/health")
def health():
    return {"status": "ok"}
```

要点：

- `app = FastAPI(...)` 创建应用实例。
- `@app.get("/")` 把函数注册为 **GET /** 的处理函数，这类函数叫**路径操作函数**。
- `return` 的字典会被自动转成 JSON 响应。

### 2.4 启动服务

在 `main.py` 所在目录执行：

```bash
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

含义：

- `main:app`：模块 `main` 里的变量 `app`。
- `--reload`：改代码后自动重启（开发用）。
- `--host` / `--port`：监听地址与端口。

看到类似输出即成功：

```text
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Application startup complete.
```

浏览器打开 [http://127.0.0.1:8000/](http://127.0.0.1:8000/)，应看到：

```json
{"message":"你好，FastAPI！"}
```

健康检查：[http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)。

也可用终端验证：

```bash
curl http://127.0.0.1:8000/health
```

```text
{"status":"ok"}
```

## 3｜自动文档：先会「试」再谈「写」

**这一节解决的问题**：不写前端，怎样方便地调试接口？

### 3.1 Swagger UI：`/docs`

打开 [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)。

页面上会列出所有路径操作。展开某个接口 → **Try it out** → **Execute**，即可看到请求与响应。这是入门阶段最省事的调试方式。

### 3.2 ReDoc：`/redoc`

打开 [http://127.0.0.1:8000/redoc](http://127.0.0.1:8000/redoc)，适合阅读式浏览接口说明。

### 3.3 与 Apifox 配合

自动文档适合开发时快速试；联调、保存用例、分享给测试同学时，用 [Apifox](../Apifox的使用方法.md)：

1. 新建 HTTP 项目；
2. 方法选 GET，URL 填 `http://127.0.0.1:8000/health`；
3. 发送，确认返回 `{"status":"ok"}`。

后续写 POST/PUT 时，同样可以在 Apifox 里配置 Body 与 Headers。

## 4｜请求怎样进到你的函数

可以把一次调用简化成：

```text
客户端  --HTTP 请求-->  uvicorn  -->  FastAPI 路由匹配  -->  你的路径操作函数
客户端  <--HTTP 响应--  uvicorn  <--  序列化返回值  <--
```

你暂时只需记住：

1. **装饰器**决定「哪个 URL + 哪个方法」进这个函数；
2. **函数参数**（下一篇起）决定「从哪里取输入」；
3. **return 值**决定「响应里有什么」（默认 JSON）。

异步写法：把 `def` 换成 `async def` 即可。本系列以同步示例为主，避免同时学两套并发模型；需要 `await` 外部 IO 时再改成异步。

## 5｜常见启动问题

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| `command not found: uvicorn` | 未激活虚拟环境，或未安装 | 激活 `.venv` 后重新 `pip install` |
| `Address already in use` | 8000 端口被占用 | 换端口：`--port 8001` |
| 改了代码没生效 | 未加 `--reload`，或改错文件 | 加 `--reload`，确认改的是正在加载的模块 |
| 浏览器打不开 | 服务未启动，或 host/port 写错 | 看终端是否仍在运行，核对 URL |
| 导入报错 | 不在项目目录，或模块名不对 | `uvicorn` 的 `main:app` 要与文件名、变量名一致 |
